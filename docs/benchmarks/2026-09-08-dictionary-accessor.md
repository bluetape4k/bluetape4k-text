# 공개 사전 조회 비용 측정 — #334

## 범위와 결정

기준 커밋 `7557332b713d9a8ee0a7b0c7b5cece2cdf3d054e`에서 같은 사전을 반복 조회하면 매번 `CharArraySet`과 키 배열을 복사했다. 한국어 전체 사전, 심각도별 금칙어, 고유명사와 일본어 금칙어의 공개 getter에 한정해 불변 뷰를 재사용한다. 내부 토크나이저의 직접 사전 조회는 이미 원본 값을 사용하므로 이 결과를 전체 토큰화 속도 개선으로 해석하지 않는다.

사전 종류마다 마지막 값과 뷰 하나만 보관하며 객체 동일성(`===`)으로 무효화를 판별한다. 기존 변경 잠금으로 캐시 공개를 보호한다. 새 값은 기존 깊은 복사 경로로 만들고 이전에 반환한 뷰는 변하지 않는다. 값을 읽은 직후 다른 스레드가 사전을 바꾸더라도 조회는 자신이 캡처한 일관된 값을 반환하며, 다음 조회에서 새로운 값에 맞는 뷰를 얻는다. 과거 revision을 계속 보관하는 캐시는 추가하지 않았다.

## 재현

```bash
./gradlew :text-search:accessorBenchmark :text-search:accessorAllocationDiagnostic --no-configuration-cache --console=plain
```

기존 `kotlinx.benchmark` harness와 tokenizer benchmark 의존성을 재사용했다. 로컬 macOS arm64 JVM에서 같은 명령으로 변경 전후를 직렬 측정했다. JMH는 warmup 1회, 측정 3회, 회당 1초이며 `ops/s` 평균을 비교한다. 할당량은 fresh JVM에서 초기 로딩 후 10회 예열하고 30회 호출하는 `ThreadMXBean` 진단으로 측정한다. 호출 결과는 소비하여 제거되지 않도록 했다. 진단 자체의 boxing/iterator 할당도 포함되므로 값이 0이어야 한다는 계약은 없다.

JMH 원본: [변경 전](assets/issue-334/baseline.json), [변경 후](assets/issue-334/after.json).

모든 공개 조회의 할당량이 99% 이상 감소했다. 초기 생성과 사전 변경 직후의 첫 조회는 여전히 깊은 복사가 필요하다. 장시간 다중 스레드 처리량은 별도로 측정하지 않았다.

## 검증과 재사용 경계

- core 165개, 한국어 203개, 일본어 100개, text-search 105개 테스트가 실패·오류·건너뜀 없이 통과했다.
- 기존 동시 reload 테스트와 취소·실패 후 초기화 재시도 테스트를 유지했고, 반복 getter 동일 인스턴스와 변경 전후 뷰의 불변성을 검증했다.
- `detekt` 통과. 공개 getter의 타입, 함수 서명, BOM 및 catalog 의존성은 바뀌지 않았다.
- 새 core 추상화나 의존성을 만들지 않았다. `SuspendMemoized`의 성공 결과만 보관하는 초기화 계약을 그대로 사용하며, 실패한 `Deferred`까지 보관하는 다른 생태계 lazy 도구로 대체하지 않았다.
