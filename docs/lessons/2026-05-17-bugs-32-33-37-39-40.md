### #32 — JapaneseBlockwordProcessor: 역방향 마스킹

**근본 원인**: 매치 토큰을 순방향으로 처리하면 앞 토큰의 마스킹이 뒤 토큰의 offset을 밀어서 위치 오염이 발생.

**수정**: `sortedByDescending { it.position }` 로 역순 정렬 후 치환.

**원칙**: 문자열 in-place 치환 시 항상 뒤에서 앞으로 처리할 것.

### #33 — OffsetMapping: NFC 합성 시 "마지막 기여자" 매핑

**근본 원인**: 동일 길이 브랜치(`else`)와 길이 감소 브랜치(`curLen < lastNormLen`)에서 `normToOrigList[curLen - 1] = origPos` 덮어쓰기를 제거하면, 첫 번째 기여자(ᄀ)가 남아 있어 마지막 기여자(ᅡ) 대신 잘못된 위치를 반환.

**수정**: 두 브랜치 모두에서 덮어쓰기 복원. NFC 합성은 "마지막으로 합성을 완성한 origPos"가 정규화 위치에 매핑되어야 함.

**테스트**: `OffsetMappingTest.NFC - 자모 분리 입력의 길이 감소 매핑 검증` + `AhoCorasickKoreanTest.NFC 정규화로 자모 분리 텍스트에서 키워드 매치`.

### #37 — DictionaryProvider: GZIPInputStream 스트림 누수

**근본 원인**: `readStreamByLine(GZIPInputStream(stream))` 에서 예외 발생 시 `stream` 이 닫히지 않을 수 있음.

**수정**: `stream.use { s -> readStreamByLine(GZIPInputStream(s)) }` 로 use 블록 적용.

### #39 — UnicodeSupport.isChinese: 데드 코드 제거

**근본 원인**: `Char.code` 의 최대값은 0xFFFF. `char.code > 0xFFFF` 조건은 항상 false (도달 불가).

**수정**: 보조 평면(> 0xFFFF) 분기를 제거하고 KDoc에 한계 명시.

---

### #40 — AhoCorasickAutomaton: lowercaseChar() 안전한 소문자화

**근본 원인**: `String.lowercase(Locale.ROOT)` 는 İ(U+0130) 같은 문자를 2글자로 확장하여 offset 매핑을 깨뜨림.

**수정**: `Char.lowercaseChar()` 로 교체 — 항상 단일 Char 반환, 길이 불변 보장.

---

## 교훈

1. 문자열 치환은 항상 역방향으로.
2. OffsetMapping의 "마지막 기여자" 의미론은 NFC 합성의 핵심 계약이다.
3. `Char.code` 최대 0xFFFF — 보조 평면은 `codePointAt`으로만 접근 가능.
4. `String.lowercase(Locale.ROOT)` 는 길이를 확장할 수 있다 — offset 민감 코드에선 `Char.lowercaseChar()` 사용.
