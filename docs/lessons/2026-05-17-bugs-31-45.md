# 회고: CharArrayMap.setValue no-op과 UnmodifiableCharArrayMap aliasing

**날짜:** 2026-05-17
**브랜치:** fix/bugs-31-45
**이슈:** #31 (`MapEntry.setValue` no-op), #45 (`UnmodifiableCharArrayMap` 문서화되지 않은 aliasing)

---

## 버그 #31 — MapEntry.setValue()가 no-op이었다

### 근본 원인

`MapEntry.setValue(newValue)`가 `_values[pos] = newValue` 대신 `_values[pos] = value`를
수행했다. `value` property getter는 `_values[pos]`를 읽으므로 이는 값을 읽은 뒤
같은 값을 다시 쓰는 no-op이었다. 표준 `MutableMap.MutableEntry.setValue` contract를
사용하는 호출자는 조용히 실패했다.

### 수정

`_values[pos] = value`를 `_values[pos] = newValue`로 변경했다.

### 핵심 교훈

Property(`value`)와 parameter(`newValue`) 사이의 name shadowing은 미묘한 버그의
흔한 원인이다. Code review는 `setValue` override의 모든 assignment를 특히 확인해야
한다.

## 이슈 #45 — UnmodifiableCharArrayMap aliasing이 문서화되지 않았다

### 근본 원인

`UnmodifiableCharArrayMap`은 shallow copy(shared backing array)를 수행하는
`CharArrayMap(src: CharArrayMap)`을 상속한다. 이는 `java.util.Collections.unmodifiableMap`
contract와 일치하지만 문서화되어 있지 않아, 호출자가 원본 reference를 버려야 한다는
사실을 알기 어려웠다.

### 수정

`unmodifiableMap()`과 `UnmodifiableCharArrayMap` KDoc을 업데이트했다.

- aliasing 동작(shared backing array)을 명시한다.
- wrapping 후 원본을 버리는 올바른 사용 패턴을 보여준다.
- Java Collections 선례를 참조한다.

### 핵심 교훈

Shared-backing read-only view는 표준 Java pattern이지만 명시적인 KDoc이 필요하다.
데이터를 copy하지 않는 wrapper는 반드시 aliasing contract를 문서화해야 한다.
