## 버그 #36 — synchronized(Any())가 virtual thread를 pinning함

### 근본 원인

`KoreanDictionaryProvider.addWordsToDictionary`는 `synchronized(Any())`를 사용했다.
JDK 21+ virtual thread는 `synchronized` block 안에서 carrier thread에 pinning되어
동시성 이점을 잃는다.

### 수정

`private val dictionaryMutationLock = Any()`를 `ReentrantLock()`으로 교체했다.
`synchronized(lock) {}`는 `lock.withLock {}`로 바꿨다.

## 버그 #38 — removeBlockwords가 3개 dictionary 중 1개에서만 제거함

### 근본 원인

`addBlockwords`는 blockWords dict, koreanDictionary[Noun], properNouns에 쓴다.
하지만 `removeBlockwords`는 blockWords dict에서만 제거해, 제거 후에도 Noun/properNoun에
단어가 남았다.

### 수정

`removeBlockwords`가 `addBlockwords`와 대칭이 되도록 세 dictionary 모두에서 제거하게 했다.

## 이슈 #41 — PunctuationProcessor가 정상 URL을 제거함

### 근본 원인

`punctuationPos`에 `URL`이 포함되어 있었다. 한국어 텍스트 사이에 있는 URL
예: `가https://example.com나`는 `maskBlockwords` 중 조용히 삭제될 수 있었다.

### 조사 결과

`Email` token은 `punctuationPos`에서 제거할 수 없다. 흔한 우회 표현인 `.@.`는
regex `[\p{Alnum}.\-_]+@[\p{Alnum}.]+`에 의해 Email로 분류되며 계속 제거 가능해야
한다. `Email`을 제거하면 기존 테스트가 깨졌다.

### 수정

`punctuationPos`에서 `URL`만 제거했다. URL은 blockword evasion에 쓰이지 않지만,
Email/Hashtag/CashTag는 evasion detection을 위해 유지한다. 의도를 문서화하도록
KDoc도 갱신했다.

### 핵심 교훈

Pattern array를 바꾸기 전에 test input의 실제 token classification을 추적한다.
Java regex의 `\p{Alnum}`은 ASCII-only([A-Za-z0-9])이므로 한국어 문자는 match되지
않는다. 이 차이가 `.@.` 같은 모호한 token을 어떤 pattern이 가져가는지 바꾼다.
