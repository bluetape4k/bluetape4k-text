# Lessons: synchronized→ReentrantLock, removeBlockwords symmetry, PunctuationProcessor URL (#36, #38, #41)

**Date:** 2026-05-17  
**Branch:** fix/bugs-36-38-41  
**Issues:** #36, #38, #41

## Bug #36 — synchronized(Any()) pins virtual threads

### Root Cause
`KoreanDictionaryProvider.addWordsToDictionary` used `synchronized(Any())`.
JDK 21+ virtual threads pin to carrier thread inside `synchronized` blocks, eliminating their concurrency benefit.

### Fix
Replaced `private val dictionaryMutationLock = Any()` with `ReentrantLock()`.
Changed `synchronized(lock) {}` to `lock.withLock {}`.

---

## Bug #38 — removeBlockwords only removes from 1 of 3 dictionaries

### Root Cause
`addBlockwords` writes to: blockWords dict, koreanDictionary[Noun], properNouns.
`removeBlockwords` only removed from blockWords dict → words lingered in Noun/properNoun after removal.

### Fix
`removeBlockwords` now mirrors `addBlockwords`: removes from all three dictionaries.

## Issue #41 — PunctuationProcessor removes legitimate URLs

### Root Cause
`punctuationPos` included `URL`. A URL flanked by Korean text (e.g. `가https://example.com나`)
would be silently deleted during `maskBlockwords`.

### Investigation Finding
`Email` token cannot be removed from `punctuationPos` — `.@.` (common obfuscation) is
classified as Email by the regex `[\p{Alnum}.\-_]+@[\p{Alnum}.]+` and must remain removable.
Removing `Email` broke the existing tests.

### Fix
Removed only `URL` from `punctuationPos`. URL is never used as blockword evasion;
Email/Hashtag/CashTag are retained for evasion detection. Updated KDoc to document the intent.

### Key Lesson
Before changing a pattern array, trace the actual token classification for the test inputs.
`\p{Alnum}` in Java regex is ASCII-only ([A-Za-z0-9]), so Korean characters are NOT matched —
this changes which patterns actually claim ambiguous tokens like `.@.`.
