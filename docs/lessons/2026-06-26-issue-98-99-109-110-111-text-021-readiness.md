# Text 0.2.1 Readiness Lessons

## Context

The 0.2.1 milestone needed examples, safety documentation, and targeted Lingua
coverage before release prep. The repository had no `examples` modules, and the
current development line was already `0.3.0`, so stable release work needed a
hard boundary.

## Decisions

- Keep examples as non-published Gradle application modules under `examples/`.
- Exclude examples from NMCP, signing, Maven publications, Dokka, and Kover
  aggregation.
- Use runnable console examples instead of adding web-server dependencies.
- Document tokenizer web-service behavior as adapter guidance: blank input maps
  to 400, oversized input maps to 413, and error bodies include only length
  metadata.
- Record readiness changes under `[Unreleased]`; leave dated 0.2.1 release notes
  for explicit release-prep work.

## Verification

- Examples `test` and `run`: PASS
- Lingua builder targeted tests: PASS
- `build -x test`: PASS
- `projects`: PASS
- `actionlint`: PASS
- README stale-version and public audit wording grep checks: PASS
- Examples task listings: no publish/sign/NMCP/Kover tasks

## Future Guidance

When adding examples to this repo, check the root `subprojects` block first.
Versionless dependencies rely on dependency management in published modules, so
non-published examples need explicit platform dependencies or equivalent version
management. Keep examples out of publication and coverage aggregation unless a
separate policy decision changes that.
