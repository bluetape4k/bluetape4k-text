# 보안 수정 회고: #48 #49

날짜: 2026-05-17

## #48 — PII 포함 예외 메시지 제거

**문제**: 예외/로그 메시지에 사용자 입력 텍스트 전체가 포함되어 PII 노출 위험.
- OWASP A09 (Security Logging and Monitoring Failures)

**수정**: `text=[$text]`, `request=$request` → `textLength=${text.length}` 로 대체.
구조적 메타데이터만 로깅하고 내용은 포함하지 않음.

**적용 위치**:
- KoreanBlockwordProcessor (findBlockwords, maskBlockwords)
- JapaneseBlockwordProcessor (maskBlockwords)

## #49 — 입력 길이 검증 추가

**문제**: 무제한 길이 입력으로 인한 CPU/메모리 소진 가능성 (라이브러리 소비자 위험).
- OWASP A04 (Insecure Design)
- KoreanChunker O(n²) 복잡도 (#42)와 결합 시 실제 DoS 벡터

**수정**:
- `MAX_TOKENIZE_TEXT_LENGTH = 100_000` 상수 추가
- `MAX_BLOCKWORD_TEXT_LENGTH = 100_000` 상수 추가
- `tokenizeRequestOf()`, `blockwordRequestOf()` 팩토리 함수에 길이 검증 추가
- 더 큰 제한이 필요한 소비자는 데이터 클래스 생성자 직접 사용

**교훈**: 라이브러리 레벨에서도 입력 경계 검증이 필요하다.
HTTP 서비스로 노출될 경우 소비자가 자체 검증을 하지 않으면 라이브러리가 DoS 벡터가 된다.
