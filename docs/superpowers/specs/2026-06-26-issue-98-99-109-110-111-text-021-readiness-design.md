# 0.2.1 Text Readiness Examples And Safety Guidance

Date: 2026-06-26
Issues: #98, #99, #109, #110, #111
Milestone: 0.2.1

## Context

`bluetape4k-text` 0.2.1 is blocked by five release-readiness issues. The
runtime APIs already exist for tokenizer request limits, Lingua detector
configuration, Aho-Corasick matching, and tokenizer blockword facades. The gap
is adoption evidence: tests that lock detector construction options, runnable
examples that use public APIs, and README guidance for service boundaries.

## Design

Add a small `examples` Gradle area with three runnable console examples:

| Example module | Issues | Purpose |
|---|---|---|
| `:examples:text-search-examples` | #109 | Demonstrate `AhoCorasickAutomaton.builder`, `ahoCorasick` DSL, `parseText`, `replaceAll`, word boundaries, and `matchesAsFlow(...).take(1)`. |
| `:examples:lingua-examples` | #110 | Demonstrate detector reuse, preloading, subset configuration, and `detectAllLanguagesOf` for Korean, English, and Japanese text. |
| `:examples:tokenizer-safety-examples` | #99, #111 | Demonstrate web-service style validation for tokenize/blockword inputs, Korean/Japanese processor calls, and sanitized error responses that do not echo raw user text. |

The root Gradle build must treat `:examples` and `:examples:*` as
non-published projects. They compile and run under CI/Nightly, but are excluded
from NMCP aggregation, signing, Maven publications, publishing configuration,
and Kover aggregation.

Example modules should use the lightest practical plugin set. They need
Kotlin/JVM, `application`, and test support; they should not inherit publishing,
signing, Dokka, Kover, or coverage work that only applies to released library
modules.

## Public API Boundaries

The examples use only released public APIs:

- `io.bluetape4k.text.search.AhoCorasickAutomaton`
- `io.bluetape4k.text.search.ahoCorasick`
- `io.bluetape4k.text.search.flow.matchesAsFlow`
- `io.bluetape4k.lingua.languageDetectorOf`
- `io.bluetape4k.lingua.detectAllLanguagesOf`
- `io.bluetape4k.tokenizer.model.MAX_TOKENIZE_TEXT_LENGTH`
- `io.bluetape4k.tokenizer.model.MAX_BLOCKWORD_TEXT_LENGTH`
- `io.bluetape4k.tokenizer.model.tokenizeRequestOf`
- `io.bluetape4k.tokenizer.model.blockwordRequestOf`
- `io.bluetape4k.tokenizer.korean.KoreanProcessor`
- `io.bluetape4k.tokenizer.japanese.JapaneseProcessor`

No production runtime behavior change is required for these issues.

## Tests And Evidence

The Lingua module adds tests for:

- convenience detector construction with low-accuracy mode enabled;
- strict `minimumRelativeDistance` behavior on ambiguous short input;
- detector reuse with mixed Korean, English, and Japanese text.

The examples add executable tests for:

- each sample `main` path;
- CI/Nightly run-smoke coverage for all three sample `main` paths;
- `tokenizer-safety-examples` sanitized failure mapping where oversized input
  returns a 413-like response without raw text leakage.
- `text-search-examples` bounded Flow scenarios, including first-alert
  `take(1)` collection, no-match collection that terminates under timeout, and
  a cancellation-propagation scenario where collecting one alert does not keep
  scanning the rest of a long input.

The release-readiness validation commands are:

```bash
./gradlew :lingua:test --tests "io.bluetape4k.lingua.LanguageDetectorBuilderTest"
./gradlew :examples:text-search-examples:test
./gradlew :examples:lingua-examples:test
./gradlew :examples:tokenizer-safety-examples:test
./gradlew :examples:text-search-examples:run :examples:lingua-examples:run :examples:tokenizer-safety-examples:run
./gradlew build -x test
./gradlew projects
```

## Documentation

Update `README.md` and `README.ko.md` consistently:

- link to the three examples from the root usage section;
- explain tokenize and blockword input limits as consumer web-service boundary
  guidance;
- describe HTTP 400/413 mapping without exposing internal security-audit text
  or raw user input.

Update module README files where they directly own the behavior:

- `lingua/README.md` and `lingua/README.ko.md` for startup/preload/subset guidance;
- `text-search/README.md` and `text-search/README.ko.md` for the runnable search example link;
- `tokenizer-core/README.md` and `tokenizer-core/README.ko.md` for request
  limit constants, validation ordering, and 400/413 mapping;
- `tokenizer-korean/README.md` and `tokenizer-korean/README.ko.md` for direct
  links to the safety example and Korean tokenizer web-service guidance;
- `tokenizer-japanese/README.md` and `tokenizer-japanese/README.ko.md` for
  direct links to the safety example and Japanese tokenizer web-service guidance.

README snippets must be copy/paste-checkable: imports, public API names, and
dependency coordinates must be consistent across root and module README files.
The validation must also reject public README wording that exposes raw internal
security audit terms, STRIDE/OWASP-style audit framing, or raw user input in
error examples.

Add an `[Unreleased]` changelog bullet for the user-visible examples, Lingua
test guidance, and tokenizer safety documentation. The dated 0.2.1 changelog
section remains release-prep work.

## Release Constraints

Before a 0.2.1 stable release, a separate release-prep step must set
`baseVersion=0.2.1`, add a dated `CHANGELOG.md` section, verify Nightly/full
validation, and dispatch release workflows only after explicit user request.
This design does not tag, publish, close the milestone, or merge.

This work still creates a normal readiness PR. The PR body must end with
`## DoD Status`, mirror the 0.2.1 milestone, keep assignee/labels aligned with
the linked issues, and record that stable release remains blocked until a
separate explicit release-prep request supplies version, changelog, Nightly, and
workflow-dispatch evidence.

## Acceptance Criteria

- #98: Lingua tests prove detector options and document startup/caching choices
  without timing-only assertions.
- #99: README locale files document tokenizer/blockword input limits and safe
  HTTP error mapping.
- #109: text-search example is runnable, test-backed, README-linked, and uses
  public APIs only.
- #110: Lingua example is deterministic, network-free, README-linked, and
  explains preload/subset tradeoffs.
- #111: tokenizer safety example validates request size before processing,
  proves oversized input is rejected before processor calls, calls
  Korean/Japanese facades through public APIs, and returns sanitized failures.
- CI/Nightly compile coverage includes the example modules.
- CI examples jobs run when example files or their upstream public API modules
  (`text-search`, `lingua`, `tokenizer-core`, `tokenizer-korean`,
  `tokenizer-japanese`) change.
- `:examples:*` modules are not part of publish or coverage aggregation.
