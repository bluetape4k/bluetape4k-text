# 0.2.1 Text 준비성 예제와 안전 가이드

날짜: 2026-06-26
이슈: #98, #99, #109, #110, #111
마일스톤: 0.2.1

## 배경

`bluetape4k-text` 0.2.1은 다섯 개의 릴리스 준비성 issue에 막혀 있다.
토크나이저 요청 제한, Lingua detector 구성, Aho-Corasick matching, 토크나이저
차단어 facade를 위한 런타임 API는 이미 존재한다. 부족한 것은 도입 증거이다.
detector 생성 옵션을 고정하는 테스트, public API를 사용하는 실행 가능한 예제,
서비스 경계를 설명하는 README 가이드가 필요하다.

## 설계

실행 가능한 콘솔 예제 세 개를 담는 작은 `examples` Gradle 영역을 추가한다.

| 예제 모듈 | Issues | 목적 |
|---|---|---|
| `:examples:text-search-examples` | #109 | `AhoCorasickAutomaton.builder`, `ahoCorasick` DSL, `parseText`, `replaceAll`, word boundary, `matchesAsFlow(...).take(1)` 사용을 보여준다. |
| `:examples:lingua-examples` | #110 | 한국어, 영어, 일본어 텍스트에 대한 detector 재사용, preload, subset 구성, `detectAllLanguagesOf` 사용을 보여준다. |
| `:examples:tokenizer-safety-examples` | #99, #111 | tokenize/blockword 입력에 대한 웹 서비스식 검증, 한국어/일본어 processor 호출, 원본 사용자 텍스트를 되돌려주지 않는 정제된 오류 응답을 보여준다. |

루트 Gradle build는 `:examples`와 `:examples:*`를 publish 대상이 아닌 project로
다뤄야 한다. 이들은 CI/Nightly에서 compile되고 실행되지만 NMCP 집계, signing,
Maven publications, publishing configuration, Kover aggregation에서는 제외된다.

예제 모듈은 실용적으로 가능한 가장 가벼운 plugin 집합을 사용해야 한다.
Kotlin/JVM, `application`, 테스트 지원만 필요하며, 릴리스되는 library 모듈에만
적용되는 publishing, signing, Dokka, Kover, coverage 작업을 상속하면 안 된다.

## 공개 API 경계

예제는 릴리스된 public API만 사용한다.

- `io.bluetape4k.text.search.AhoCorasickAutomaton`
- `io.bluetape4k.text.search.ahoCorasick`
- `io.bluetape4k.text.search.flow.matchesAsFlow`
- `io.bluetape4k.lingua.languageDetectorOf`
- `io.bluetape4k.lingua.detectAllLanguagesOf`
- `io.bluetape4k.tokenizer.model.MAX_TOKENIZE_TEXT_LENGTH`
- `io.bluetape4k.tokenizer.model.MAX_BLOCKWORD_TEXT_LENGTH`
- `io.bluetape4k.tokenizer.model.tokenizeRequestOf`
- `io.bluetape4k.tokenizer.model.blockwordRequestOf`
- `io.bluetape4k.tokenizer.korean.KoreanProcessor`
- `io.bluetape4k.tokenizer.japanese.JapaneseProcessor`

이 issue들을 위해 production 런타임 동작을 바꿀 필요는 없다.

## 테스트와 증거

Lingua 모듈은 다음을 위한 테스트를 추가한다.

- low-accuracy mode가 활성화된 편의 detector 생성
- 모호한 짧은 입력에 대한 엄격한 `minimumRelativeDistance` 동작
- 한국어, 영어, 일본어 혼합 텍스트에서의 detector 재사용

예제는 다음을 위한 실행 가능한 테스트를 추가한다.

- 각 sample `main` 경로
- 세 sample `main` 경로 전체에 대한 CI/Nightly run-smoke coverage
- 과도하게 큰 입력이 원본 텍스트 유출 없이 413과 유사한 응답을 반환하는
  `tokenizer-safety-examples`의 정제된 실패 mapping
- 첫 alert `take(1)` 수집, timeout 안에 종료되는 no-match 수집, alert 하나를
  수집한 뒤 긴 입력의 나머지를 계속 scan하지 않는 cancellation 전파 시나리오를
  포함한 `text-search-examples`의 bounded Flow 시나리오

릴리스 준비성 검증 명령은 다음과 같다.

```bash
./gradlew :lingua:test --tests "io.bluetape4k.lingua.LanguageDetectorBuilderTest"
./gradlew :examples:text-search-examples:test
./gradlew :examples:lingua-examples:test
./gradlew :examples:tokenizer-safety-examples:test
./gradlew :examples:text-search-examples:run :examples:lingua-examples:run :examples:tokenizer-safety-examples:run
./gradlew build -x test
./gradlew projects
```

## 문서

`README.md`와 `README.ko.md`를 일관되게 업데이트한다.

- 루트 사용법 섹션에서 세 예제로 연결한다.
- tokenize와 blockword 입력 제한을 consumer 웹 서비스 경계 가이드로 설명한다.
- 내부 security-audit 텍스트나 원본 사용자 입력을 노출하지 않고 HTTP 400/413
  mapping을 설명한다.

해당 동작을 직접 소유하는 모듈 README 파일을 업데이트한다.

- `lingua/README.md`와 `lingua/README.ko.md`: startup/preload/subset 가이드
- `text-search/README.md`와 `text-search/README.ko.md`: 실행 가능한 search 예제 링크
- `tokenizer-core/README.md`와 `tokenizer-core/README.ko.md`: 요청 제한 상수,
  검증 순서, 400/413 mapping
- `tokenizer-korean/README.md`와 `tokenizer-korean/README.ko.md`: safety 예제 직접
  링크와 한국어 토크나이저 웹 서비스 가이드
- `tokenizer-japanese/README.md`와 `tokenizer-japanese/README.ko.md`: safety 예제
  직접 링크와 일본어 토크나이저 웹 서비스 가이드

README snippet은 copy/paste로 검증할 수 있어야 한다. import, public API 이름,
dependency coordinate가 루트와 모듈 README 파일 사이에서 일관되어야 한다. 또한
검증은 public README 문구가 원본 내부 security audit 용어, STRIDE/OWASP식 audit
프레이밍, 오류 예제의 원본 사용자 입력을 노출하는 경우를 거부해야 한다.

사용자에게 보이는 예제, Lingua 테스트 가이드, 토크나이저 안전 문서를
`[Unreleased]` changelog bullet에 추가한다. 날짜가 붙은 0.2.1 changelog 섹션은
release-prep 작업으로 남긴다.

## 릴리스 제약

0.2.1 stable release 전에는 별도 release-prep 단계에서 `baseVersion=0.2.1`을
설정하고, 날짜가 붙은 `CHANGELOG.md` 섹션을 추가하고, Nightly/full validation을
검증한 뒤, 명시적인 사용자 요청이 있을 때만 release workflow를 dispatch해야
한다. 이 설계는 tag 생성, publish, milestone 종료, merge를 수행하지 않는다.

이 작업은 일반 readiness PR을 생성한다. PR 본문은 `## DoD Status`로 끝나야 하며,
0.2.1 milestone을 반영하고, assignee/labels를 연결된 issue와 맞추고, 별도
명시적 release-prep 요청이 version, changelog, Nightly, workflow-dispatch 증거를
제공하기 전까지 stable release가 계속 막혀 있음을 기록해야 한다.

## 인수 기준

- #98: Lingua 테스트는 timing-only assertion 없이 detector 옵션과 startup/caching
  선택을 증명한다.
- #99: README locale 파일은 tokenizer/blockword 입력 제한과 안전한 HTTP 오류
  mapping을 문서화한다.
- #109: text-search 예제는 실행 가능하고, 테스트로 뒷받침되며, README에 연결되고,
  public API만 사용한다.
- #110: Lingua 예제는 결정적이고, network-free이며, README에 연결되고,
  preload/subset tradeoff를 설명한다.
- #111: tokenizer safety 예제는 처리 전에 요청 크기를 검증하고, 과도하게 큰 입력이
  processor 호출 전에 거부됨을 증명하며, public API를 통해 한국어/일본어 facade를
  호출하고, 정제된 실패를 반환한다.
- CI/Nightly compile coverage는 예제 모듈을 포함한다.
- 예제 파일이나 upstream public API 모듈(`text-search`, `lingua`,
  `tokenizer-core`, `tokenizer-korean`, `tokenizer-japanese`)이 변경되면 CI examples
  job이 실행된다.
- `:examples:*` 모듈은 publish 또는 coverage aggregation 대상이 아니다.
